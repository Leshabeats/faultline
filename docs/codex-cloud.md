# Codex Cloud runtime

Use a clean repository checkout in a Linux VM. No Docker, production data, external service or secrets are required. Configure the Cloud setup command as `bash scripts/codex-cloud/install.sh`. A maintenance run can use the same idempotent command. Run `bash scripts/codex-cloud/check.sh` after changes. Start a preview with `bash scripts/codex-cloud/start.sh` and stop it with Ctrl-C or SIGTERM.

Runtime: Node.js 24.13.1 with bundled npm 11.8.0. Linux x86_64/arm64 and macOS arm64/x86_64 are supported. The scripts download a missing runtime into ignored `.codex-cloud/`, validate SHA-256 against the official vendor manifest, and never change global tools. npm uses an isolated repository cache. Every install uses committed lockfiles via `npm ci`; lockfiles are never generated by setup. Native SQLite may require Python 3, make and a C++ compiler if a prebuilt binary is unavailable. Provision those OS packages in the Cloud environment rather than disabling install scripts.

Ports: 4173 (Vite, 0.0.0.0), 8787 (API, loopback). Data: .codex-cloud/faultline.db. Run start in the foreground; its trap stops only its child processes. Port conflicts fail rather than reusing a running application. VM preview access controls should restrict forwarded ports to the task owner.

Required environment keys: none. Do not import local `.env`, tokens, production SQLite files, private keys or home-directory state. `.codex-cloud/` and generated dependencies are disposable and ignored.

Network during setup: `nodejs.org`, `registry.npmjs.org`; native prebuild downloads can use `github.com`, `release-assets.githubusercontent.com`, and `objects.githubusercontent.com`. Checks require no paid API calls. Vendor binaries use HTTPS and SHA-256 manifests; dependency integrity is enforced by npm lockfiles.

Shared skills live in the private repository `github.com/Leshabeats/codex-skills`, pinned to commit `13b36a8ffef7dc8eab6d57e1c1519e1e514509d2`. Configure an additional authorized source checkout in Cloud and set `CODEX_SKILLS_SOURCE` to its directory. Verify `git -C "$CODEX_SKILLS_SOURCE" rev-parse HEAD` against the pinned commit, then run `python3 "$CODEX_SKILLS_SOURCE/install.py" --source "$CODEX_SKILLS_SOURCE" --project "$PWD" --profile core`. Do not embed credentials in commands or copy generated shared skills into product commits. These project scripts do not automatically clone or execute `CODEX_SKILLS_REPO`/`CODEX_SKILLS_REF`. Cloud environment setup remains a manual configuration step until project changes are committed and pushed.

Validation status is reported in the preparation report; preparing these scripts alone does not prove a live Codex Cloud environment was created.

Go 1.22.12 is provisioned from `go.dev` (redirecting to `dl.google.com`) and checksum-verified against the official Go release API. Module downloads use `proxy.golang.org` and `sum.golang.org` (Google storage redirects may occur). `go.sum` is required and `go mod verify` runs during setup. Checks run frontend tests/build and backend tests/vet. The preview stores fresh SQLite data in `.codex-cloud/` and refuses .env files. Interview providers remain the existing offline provider.

When `CODEX_SKILLS_SOURCE` is set, install.sh invokes shared-skills.sh, verifies the pinned SHA (or explicit CODEX_SKILLS_REF), and installs the core profile automatically. The generated bundles are ignored; the project cloud-runtime skill remains tracked. Git and Python3 are prerequisites for this optional step. No network token is fetched.
